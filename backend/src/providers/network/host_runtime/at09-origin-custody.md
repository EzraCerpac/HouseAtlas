# Verified inventory origin custody

Current source already supplies passive GET /api/inventory, the normal verified
reqwest 0.13.5/Rustls client, full reviewed shared-home membership, original
observations/review/confidence/fact/retrieval dates, genuine lifecycle grants,
same-Store publication/disclosure pins and private cross-open native custody.
The remaining origin gap was between that real fetch and later retained reads:
the native archive stored source/body/receipt context without the reviewed origin.
This donor binds those existing production paths rather than substituting peers.

InventoryTransport::get_inventory_with_custody is additive. Its default wraps
an existing InventoryResponse in CustodiedInventoryResponse::unattested. Existing
response literals and offline/injected transports remain compatible. Only the
concrete HttpInventoryTransport creates InventoryOriginCustody, after normal TLS,
exact endpoint, response, complete bounded body, original authority and deadline
checks. Custody has no public constructor, Clone, Serde or URL/header accessor.
The provider consumes it against the exact full registration and raw body SHA.
OriginalNetworkCapture remains cloneable evidence data with its existing fixed
generation context; copied metadata supplies no permission or freshness grant.

The canonical origin fingerprint is SHA256 over the domain/version and exact
GET /api/inventory route plus the configured canonical HTTPS origin. It contains
no URL/header/credential bytes. The original private segment header gains optional
origin_sha256; missing fields default to absent and skip serialization, preserving
legacy header byte reserialization. Unknown/legacy/injected origin is never
upgraded or inferred. Capacity admission reserves the bounded extra header field;
raw body bytes, receipts, catalog, permanent IDs and schemas remain unchanged.

Native runtime requires matching proof before starting a projected stage and
requires matching archived origin before accepting a retained projection. The
raw reopen verifies and reprojects private owner bytes before this comparison;
those bytes are not released by that phase. Retained
origin fingerprints are provenance DATA. Native header integrity, original
registration/body/projected receipt, full review/member checks, same-Store pin
and current original authority are still mandatory. No public DTO or storage
projection gains an origin field. A runtime whose configured origin changes for
the same registration cannot adopt originless or different-origin cached bytes.
Older raw archives remain inspectable by their existing low-level trusted owner;
they are unavailable to genuine runtime reads until an independently authorized
fresh concrete capture exists. No automatic migration, rehash or rewrite occurs.

The additional pure disclosure-origin tag is proposed separately where required
by the reserved source owner; later rerelease must compare the original tag to
the current runtime before original grant checks, without hidden file I/O under
an authority callback. This source document does not assert that pending glue is
accepted. The separate fresh fixture proposals carry their entire imports/main/
helper bodies and are compiler checked; execution requires the exact named
healthy source reservation and inspection. No broad runtime/test alias is used.

Root declarations, manifests, router, migrations, shared schemas and CI are
untouched. The same compiled normal client profile is used; no parallel client,
new credential/grant, provider call, deployment, /api/snapshot, ARP, diagnostics,
collector demand, import or upstream write is supplied. Native recovery/export/
future producer completeness remains Unknown and protects all. No retention
window, reclamation executor, deletion or stopped control is introduced. Source
and isolated synthetic proof remain distinct from live AT09 acceptance.

Integration uses existing http module reexports and the existing native runtime;
no additional root mount or dependency is required for the approved production
slice. The normal reqwest 0.13.5 declaration already supplies this client profile.
The concrete healthy fixture is proposed separately, including three helper
functions (owner_error, evidence, core_state), its full main and a bounded local
TLS driver. It has not run. The older network-disclosure-pin fixture deliberately
injects an unattested response; its native-runtime browse is no longer a healthy
origin-qualified case and needs an independently reserved genuine TLS adapter.
No fake custody issuer or implicit legacy origin adoption may repair that case.

Strict library and example Clippy pass on the exact source composition. All-target
Clippy is blocked by an unchanged Homebox credentials_healthy.rs fixture retaining
a MutexGuard across await. That file is outside this donor and remains untouched.
These are compilation results, not runtime, Mac or live provider qualification.
