# Native geodata document seam

This unselected backend seam retains TIFF, GeoJSON and CityJSON originals as
`evidence-original` with `download-only`. Provider intake retains its existing
PNG/JPEG/PDF/text allowlist. Raw sources are bounded to the existing10MiB limit
and validated as download envelopes; no TIFF decompression, GIS interpretation,
source URL request, ZIP extraction or coordinate registration runs here. Classic
TIFF is supported; BigTIFF and ZIP remain unsupported. The CityJSON download
profile also retains official 3DBAG API single-feature and bounded batch
envelopes with separate CityJSON metadata. A batch contains CityJSONFeature
objects rather than GeoJSON features; its original bytes, quantization metadata
and counters remain unchanged. This establishes framing, not spatial validity.

`houseatlas.geodata-document.v1` pins workspace/home, immutable document revision,
original asset ID/revision/SHA256/bytes, provenance and optional preview lineage.
Source provenance keeps agency, private source URL, license, distinct retrieval,
publication and observation dates, explicit date precision, nullable CRS/units/
extent and source custody receipt digest. Unknowns remain null; source metadata
proves neither physical placement nor building membership.

The first preview profile accepts one original input and a separately retained
PNG derivative. It pins input and output asset identities, renderer/version,
config digest, qualification receipt digest, nullable source crop extent and a
short description of the derivation. PNGs use the native-only
`application/vnd.houseatlas.geodata-preview+png` retained family with
`derived-preview`; the source-aware read emits validated stripped `image/png`.
The bare media service refuses this new derivative family so it cannot bypass
the original/document relationship. Existing original PNG behavior is unchanged.

`qualify` verifies exact source/PNG bytes, framing, same scope, immutable asset
revisions, availability, purpose, source/preview license equality and lineage.
`PreviewQualificationPort` additionally verifies a separately approved retained
renderer receipt against these pins. A client-provided receipt digest alone is
insufficient. No real qualification-port implementation is selected here.
Composite multi-source previews require a separate reviewed extension.

`read` uses explicit storage and access ports, checks document/home and input
records, and re-reads authoritative records and the grant after byte work. A
preview also revalidates the qualification port before emission. Original
download is independent of an optional preview's availability. Read results
contain bytes/type/disposition only; source URLs are not emitted as media links.
The transport adapter must add private/no-store, nosniff, sandbox and appropriate
attachment/inline headers immediately on emission.

## Integration still required

No HTTP route, native write command, graph schema/migration, frontend projection,
production converter, persistent receipt reader or household import is installed.
The owning backend integration must connect authenticated document read/projection
and audited atomic document+asset admission, grant/revision checks and a reviewed
retained renderer-receipt reader. Route ownership must prevent any alternate bare
asset grant from delivering geodata PNGs. Building association needs its own
verified native binding. The frontend owner consumes the Documents projection;
the deployment owner alone performs native intake after release review.

## Named healthy synthetic checks

Inspect `geodata_original.rs`, `geodata_document.rs` and
`geodata_document_healthy.rs` before running the exact commands in the verification
guide. These examples use generated bytes and explicit in-memory scope/access/
qualification stubs. They prove bounded framing and original/preview read
composition, not real renderer execution, persistent admission, production access
control or georeferenced household acceptance. No listener/provider is invoked.

## Archive custody

The retained ZIP can remain in private archive custody while individual source
originals under the existing10MiB bound are admitted through a future reviewed
native route. This slice adds no ZIP format, larger quota, archive streaming,
extraction, native import or change to the global media limit.
