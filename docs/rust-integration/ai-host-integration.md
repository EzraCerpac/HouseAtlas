# AI host composition

The root compiles the actual AI modules and browser host with the Rust HTTP,
Access and SQLite application. The optional host remains unconfigured in the
binary. Without a bound host, Settings omits AI and Lantern hides Ask. No
client, registration, credential or inference admission is created.

## Native app mounting

`http::ai::mounted_router` requires a genuine host API and enrollment owner.
`router_with_ai` mounts it beneath the existing workspace/home AI path and
checked-header, admission and private-response middleware. The original Axum
URI and actual Access principal are retained across asynchronous native-context
capture. JSON actor fields, registration labels or copied grants cannot replace
that context. Final result release revalidates the same principal and enrollment
binding; the narrow persisted-disconnect receipt proof preserves the actor,
home, registration and authority epoch while allowing its intentional
cancellation-epoch change.

Browser host composition requires the complete actor/session/home/registration/
cancellation-epoch scope and a stable genuine application client. Current-source
operation correlations and bounded retry state do not create credentials or
provider authority. Earlier stale source and compiler attempts are retained
separately in private evidence, with no acceptance claim.

endpoint, with `store=false`, `stream=true` and a completed terminal event.
