# Native host corrections

The host preserves the actual MCP owner's bounded response bytes. It no longer
adds a null request ID to an unidentified error. Root HTTP intake errors also
omit the ID when no request has been identified. Known string or numeric IDs
remain the owner's original values. This follows the selected
[MCP 2025-11-25 error schema](https://modelcontextprotocol.io/specification/2025-11-25/schema#jsonrpcerrorresponse),
whose ID is optional. The framing correction is reviewed from source only;
no error, malformed-input or rejection probe is run.

The additional cached HomeBox query route carries opaque collection identities
as data. Existing scope authorization, trusted registration equality, source
grant capture, canonical cached projection and final original-authority release
remain required. The old path route remains available for its existing clients.
No provider client, credentials, refresh or freshness update is introduced.

The selected healthy Unicode fixture is a fixed public-data adaptation, applied
before the actual Access and Atlas databases are populated. Its collection
contains spaces, slash, question mark, Greek alpha, plus and percent. All eight
matching source keys are changed together, including stored unverified link
descriptors. UUIDs, payloads, provenance, cache status, source dates, retrieval
dates and generation remain otherwise unchanged. The explicitly named browser
runner performs only authorized reads through the actual TLS service and React,
then observes real SQLite rows read-only. No encoded-path rejection request is
sent as a comparison.

The existing place-admission transport limits remain 2048 UTF-8 bytes of decoded
SourceRef JSON and 4096 encoded query bytes. The concrete TypeScript client now
checks both before fetching, retaining the entire selector. This is the stated
disposable profile's coverage, not a narrower shared contract. Wider source
transport and cached configuration for header-ineligible identities require
their separate owner work.

Previously stopped guard, adversarial, rejection, replay, expiry, revocation,
fault, crash, concurrency and provider controls remain unrun. No deployment or
product acceptance follows from these corrections or the ordinary examples.
