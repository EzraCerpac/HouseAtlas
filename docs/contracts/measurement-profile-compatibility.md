# Measurement profile compatibility and recovery

Measurements use the distinct outer lineage
houseatlas-rust-storage/geodata-measurements/1, catalog 1, measurement contract 1.0.0
and recovery format houseatlas-native-geodata-measurements-recovery/1.
Measurement record schema remains 1. Base 5, stock 6, presence 7, held 8 and
Document 2.0.0 semantics are unchanged. Existing openers still refuse the extra
catalog; no compatibility inference follows from sharing SQLite or old tables.

## Explicit selection and composition

MeasurementProfileSelection defaults to Disabled. The disabled path keeps the
existing opener. MeasurementsV1 requires an already compatible image and genuinely
reviewed persistent-state binding, original Access/vault ownership, Document
policy and publication-owner inputs. The feature creates/adopts/provisions no
image and performs no existing-data migration or startup conversion. No release
profile, runtime configuration or service selection is activated by this increment.

Both persistent startup paths compose the strict opener and Host.with_measurements.
Required stored inventory is validated before any session; configured semantic
exports remain bounded pinned INPUTS at startup. A client hint is emitted only
after successful composition and is informational, never source/mutation authority.
The backend has no dependency on a frontend inspector/client/helper mount.

Per-input descriptors distinguish current publication owners from explicitly
retained publication owners. Current owners reuse the exact Host allocations;
retained inputs use genuine existing overview/scene validators. Configured paths
or decoded descriptors are not grants. Each request qualifies actual native
mapping/review evidence under its SAME original authenticated guard. There is no
startup principal, reauthorization around denial, global mutable occurrence or
historical-room-link shortcut. Opaque historical receipt context never discovers
or opens producer files; only separately configured retained inputs may do so.

## Catalog and same-store data

The catalog pin covers the ordered seven DDL inputs: five existing native ledger
inputs, geodata_full and the new measurement DDL. Native ordinals remain exact.
The facet's five tables share the authoritative Atlas SQLite connection. Complete
immutable mutation receipts alone hold measurement values/history; heads are
CAS pointers, audit rows correlate immutable commits, and pending/outcome state
is atomic with them. There is no second connection, parallel ledger or shadow
value journal. Existing native/Document history, media and reference validation
remain part of combined qualification.

The schema URI is
https://houseatlas.invalid/contracts/measurement-assertions/1.0.0/atlas.schema.json.
Only its named generator mode owns generated carriers; no hand-edited generation
or canonical schema identity change is included in source formatting.

## Normal reopen, capture and restore

Normal existing-image reopening validates guarded WAL mode, NOFOLLOW/file identity
and complete combined inventory without converting modes. Standalone detached
recovery images are independently required to use DELETE mode. Those paths remain
separate; a startup shortcut must not treat one as evidence for the other.

Capture, bundle verification and fresh restore retain native/Document ancestry,
required media bytes, receipts, heads, audits, outcomes and pending work. Strict
combined validation is required before returning Store/binding. Fresh restore
uses a new Store/Access/vault instance allocation; stale handles cannot be reused.
The measurement image has honest rollback limits: an old opener must refuse its
catalog, and this feature supplies neither a downgrade nor migration/backfill.

## Optional historical producer context

Only schema-valid bounded original pins correlated to intact immutable receipts,
audits, scope and required native references may be retained as opaque recorded
context. This exception applies only to originally Unknown custody AND Unknown
physical registration without a required custody dependency. Do not dereference
unknown producer content during inventory qualification or label it file missing,
available, accepted geometry or native Evidence qualification.

Returned inventory reports distinguish recorded-context-unverified from qualified
required lineage. Malformed data, hash mismatches, missing required references or
media still refuse open/capture/restore. Optional historical producer unavailability
is not a waiver of required native/Document/media integrity or source authorization.
Saved values survive independently of current applicability, but disclosure still
requires current original read/source grants. Incomplete comparison never becomes
an empty successful consistency result or permission to mutate.

## Semantic export input contract

A private semantic export uses profile
houseatlas.private-measurement-semantic-export.v1 and exact scope, publication,
source revision/hash, artifact ID/model bytes/hash, semantic occurrence/part pins,
occurrence-to-native-record mapping, retained mapping-review Evidence mutation
identity, and qualified method/support/evidence inputs. The exact raw export hash
must correlate to genuine retained native review evidence and accepted semantics.
No public fixture contains actual household inputs. No native receipt, Evidence,
Geometry, SceneAssociation, registration or geometry acceptance is manufactured.

Pairwise association carries an immutable request-local REFERENCE target/admission
and qualifies its original owner under the original guard before evaluating the
candidate. Possessing two owners or matching room identity/area is insufficient.
Distinct parts/publications remain review-required/unavailable without reviewed
correspondence; authorized history remains preserved.

## Qualification boundaries

Selected generated native cases historically cover disabled selection, strict
open, authenticated create/correct/context/current/history/outcome, two-part
comparisons and configured retained-owner availability. Separate exact-tree
personal-entry/history and retention qualifications remain historical evidence.
A later preservation audit may qualify already completed client cases; no native
or client run is repeated or inferred by this source integration. The verification
guide records candidate selectors and held classes.

This backend-only candidate still needs exact-source generation consistency,
format checking, compilation, warning-free Clippy and the existing integration
pipeline under a new explicit release. Source placement supplies no compatible
image/binding issuer, runtime activation, browser/device/physical-model acceptance,
