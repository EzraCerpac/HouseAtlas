# Native original document read port

`createNativeDocumentReadClient` is the source port for an explicit original-document click. In the product it is reached only through `createNativeEvidenceDocumentClient`, which `frontend/integration/main.tsx` wires into the saved evidence view, the Electrical Library reader and the Unified Atlas reviewed overlays. The assistant scan intake compiles `frontend/integration/native-scan-import-scene.ts`, which uses the same wrapper. `frontend/integration/native-scan-import-text.ts` calls the port directly; no current command loads it. The private host supplies its current opaque `sessionIdentity`, expiry, exact workspace/home scope, canonical HTTPS origin and synchronous binding subscription. The client issues no session, cookie, CSRF token, grant, upload or import. No package place ID, source filename, storage key or documentary label substitutes for a retained Atlas asset UUID.

`loadOriginal(expected, signal)` requires the genuine asset ID, exact original MIME and SHA256, and an `ExactDecimal` byte size from retained evidence. An optional retained `ExactDecimal` revision must match as well. It performs a Stock3 `atlas.asset.get` GET through the actual native scoped record route, one original Media download, and a final GET of the same record. The existing pinned lossless Stock validator checks the complete closed read result. Exact scope, one active/available original asset, current source status, target identity, MIME, digest, byte size and owner download policy must match. The final record must retain the same exact revision and metadata. The server generates this GET's request ID; the client validates its schema and correlates the actual scope/target rather than fabricating an echoed request ID.

The Media route digest is SHA256 of the canonical `{assetId, kind: 'atlas-asset'}` descriptor. It is separate from the original file SHA256. The native owner freshly authorizes that route and validates the original. The client verifies its exact response MIME, declared and streamed byte length, and actual SHA256. Only the existing original PDF, JPEG, PNG and UTF-8 text families are accepted, under the owner's `safe-rendered` or `download-only` policy and original purpose. An original is not promoted to a safe rendered preview. Native PDF validation establishes framing, not document safety.

All requests use the exact same native origin, `credentials: 'same-origin'`, `mode: 'same-origin'`, `cache: 'no-store'` and `redirect: 'error'`. The requested Origin is the canonical host origin. Browsers own transport Origin and Sec-Fetch-Site headers; this code never spoofs Sec-Fetch-Site or provides a cookie. The actual native GET boundary also admits a browser-owned same-origin fetch/referrer when Origin is absent. If browser metadata or current native access is unavailable, the read fails without an authorization fallback.

One explicit operation has a 15-second whole header/body/hash deadline, a 128-KiB metadata response bound, an 8-KiB response-header bound, bounded chunks and a 10-MiB original byte bound. Duplicate JSON keys, excessive depth/nodes/strings and unsupported closed result shapes are rejected before capability release. Numeric metadata remains lossless through the existing exact parser/validator. Only the proven small byte count becomes a Number for bounded stream comparison. These bounds do not promise a fixed browser heap, GPU budget or server cancellation: temporary chunks, assembled bytes, digest work and Blob storage can coexist, and synchronous work can settle after a timer's nominal instant.

The returned `NativeDocumentFrame` contains readonly metadata and an opaque local lease. The client privately retains at most one Blob and one in-flight operation. `getBlob(frame)` returns the immutable original only while `isCurrent(frame)` holds. A new click first withdraws the prior frame; a failed new read does not restore it. Binding replacement/gap, expiry, release and disposal synchronously withdraw the capability, notify subscribers and abort owned work. Every asynchronous boundary checks the captured owner and reserved operation generation. Reentrant invalidation callbacks cannot let an older operation replace a newer frame. Already invalid subscriptions notify immediately.

The UI owner subscribes before displaying a Blob, rechecks currentness after creating its object URL and revokes/removes that URL synchronously on invalidation, close and unmount. PDF navigation may add an explicitly selected `#page` fragment to that UI-owned object URL. The client creates no object URL, returns no native route/download handle and stores no original persistently. It cannot erase a Blob already handed to another caller or revoke a URL created by the UI; the host must enforce that display lifecycle. A lease fences this local observation and never replaces fresh native authorization or proves continuous server record freshness.

This reservation changes only the new client, types and this document. No host mounting, styles, backend, shared contracts, helpers, README or manifests are changed. Source review and separately authorized checks remain required. Installed readiness remains on the previously qualified artifact; zero native PDF assets have been established by this work, and no drawing availability or successful PDF click-through is claimed.
