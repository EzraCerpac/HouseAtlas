# Synthetic native-produced geometry reader

The README registers this paired healthy cross-language case. The reviewed local
execution passed native custody, strict reopen and cleanup, then read the exact
produced descriptor and mesh bytes through the actual TypeScript client, profile
decoder and render preparation. This qualifies the synthetic reader seam; it
establishes no native mounting, browser, converter authenticity or private intake.

The installed baseline has two distinct positives. The Rust custody example
generates a synthetic USDZ framing original and closed authored mesh, commits
their native custody and building association, reads the actual descriptor and
mesh through its in-process authenticated HTTP router, and verifies strict
reopen and native scratch cleanup. The frontend reader positive constructs its
own descriptor and profile Responses. This paired bridge passes the
exact Rust-produced GET response bodies and selected observed headers through
`createNativeGeometryReadClient`, `readScanMesh` and `prepareMeshRender`.

## Create-only output contract

The optional `HOUSEATLAS_GEOMETRY_SEAM_EVIDENCE` path must be absolute, have an
already existing canonical parent owned by the operator, and name a new directory.
Root verifies ownership and privacy of the selected parent; the emitter checks
its canonical path but does not inspect that parent's UID or permissions.
The Rust body creates the child exclusively at mode 0700. Existing targets fail without
being adopted, deleted, resumed or overwritten. Fixed files are opened with
`create_new`, mode 0600. On partial emission, it attempts to remove only that newly created
directory. Cleanup failure does not replace the original emission error; the
operator must verify removal before reusing the selected parent. The option is absent by default; the existing command emits nothing
new and retains its original fixture, assertions, disposal and printed result.

The directory contains exactly:

- `descriptor.json`: exact native GET bytes, at most 1 MiB.
- `mesh.json`: exact native GET bytes, at most 8 MiB.
- `produced-read.json`: at most 16 KiB, the schema
  `houseatlas.synthetic-native-produced-read.v1`. It records the synthetic origin,
  actual descriptor scope, synthetic building ID, fixed response filename and
  owner route, successful status, byte size and SHA256 for each response, the
  three native protocol hashes, and completed native cleanup/reopen provenance.

Only observed `content-type`, optional `content-length`, `cache-control`,
`x-content-type-options`, `content-security-policy` and
`x-atlas-geometry-view` response headers are retained. Absent headers remain
absent. Each selected-header JSON is bounded to 8 KiB. No session, cookie, CSRF,
credential, token, authorization header, grant, store path or original response
envelope is emitted. The output is synthetic local evidence, not native custody
for a household or a cryptographically authenticated provenance receipt.

The consumer requires canonical mode-private regular files, reads only the
three fixed names, checks exact size/digests and the closed capture manifest,
then provides exactly two streamed Responses using these bytes and observed
headers. It makes no real Fetch call and opens no listener. A deliberately
synthetic current binding fences the actual client; it is not native authority.
Chunks are 64 KiB. No observer or timer remains after client disposal. The
consumer writes no files and leaves the evidence for Root's retained readback.
Root owns removal of this newly selected evidence directory after retention.

## Assertions and limits

The consumer checks the actual native floor path, frame header, derivative
digest, original lineage, asset/geometry/evidence revisions and separate licence
data; it preserves authored negative zero, the complete two-node transform chain,
composed translation and the pinned native producer identifiers. It prepares one
triangle's display buffers while preserving source tokens, zero semantic rooms,
unknown physical scale/alignment and null stage-to-house transform. It disposes
the client and checks that its binding subscription is removed before printing
PASS, plus the observed descriptor/mesh SHA256 values.

The USDC-signature archive is synthetic framing, not a parsed or converter-made
USD scene. Protocol hashes are data, not proof of conversion authenticity. This
case does not authenticate producer claims, qualify the retained private three
floor exports, establish live browser/GPU availability, align floors, bind rooms,
register electrical drawings, qualify capture/fallback/restore, or accept service
installation. Actual household custody/readback and the mounted application
remain separate obligations. No earlier real upload is reconciled or resent by this case.
