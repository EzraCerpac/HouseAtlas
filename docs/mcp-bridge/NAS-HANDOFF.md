# NAS source handoff — no activation

The sole NAS owner stages and verifies the immutable private Library artifact.
This coding task does not enter/transmit real credentials, grant access, change
network configuration, compile on Mac/NAS or activate a service. Preserve all
existing services. Original artifacts/source freezes remain unchanged; any source
change needs a new artifact, hashes, exact-head review and CI record.

The revised source rejects duplicate launch-spec properties before command
construction, executable inspection or runtime-key access. Exact native integral
revision spellings are supported without changing request bytes. Commit/retained
results have the explicit bounded profile in README.md; oversized/unrepresentable
results still require separate native custody and keep UNKNOWN. A confirmed large
retained response may return explicit metadata in MCP while its complete bytes
remain in the private journal. These source changes do not qualify or activate an
existing installation; any earlier NAS evidence stays pinned to its own source.

## Private deployment contract

Target account paths, UID, executable paths/versions/hashes/modes and registration
are host settings and remain outside Git. Public source contains no observed host
pins. The private artifact carries the separately reviewed installer metadata;
that metadata does not itself qualify the installed host or release activation.

The installer creates only `<installed-root>/deployment.json`, a bounded closed
nonsecret object with `schemaVersion:1`, `uid`, `root`, `config`, `state`, `tunnel`
and `python`. Root/config/state are distinct absolute canonical directories. Both
executable descriptors contain exact `path`, lowercase `sha256`, integer `uid`
and integer POSIX `mode`; tunnel additionally contains exact `version`. This
source supports the inspected tunnel-client0.0.14 CLI only. Metadata cannot add
argv, URLs, environment, native cookies or arbitrary command templates.

The bootstrap path is derived solely from the canonical installed script layout,
never CLI, environment or MCP tool input. Installed root must already be owned0700;
`deployment.json` must be owned0600, regular, nonsymlink and single-link. UID must
match real/effective current UID. Wrapper and launcher load only their validated
fixed neighboring key-entry source for the common metadata validation. Keep the
nested and stable top-level key-entry.py byte-identical. Host changes require a
new reviewed private metadata contract, never executable discovery or fallback.

## Inspectable staging recipe

1. Materialize the exact private Library artifact. Verify its archive SHA256 and
   all manifest members. Inspect source commit/tree, independent review and
   exact-head CI. Never patch an old archive or compile on Mac/NAS.
2. Stage only into the new owner-approved canonical0700 installed root. Preserve
   payload layout, public operation catalog and the matching top-level key setter.
   Do not overwrite an installation or unrelated service. Create the new0600
   deployment metadata only after the NAS owner approves every actual host pin.
3. Prepare new owned0700 config/state roots from that contract; preserve existing
   parents. Create only owned0600 `bridge.json` with approved native `origin` and
   native workspaceId/homeId, and `launch-spec.json` with `configured` and the
   existing `registrationId`. The source example remains configured:false.
   No native cookie file is accepted or created.
4. Qualify genuine canonical HTTPS `/auth/proxy`, current native session and scoped
   Editor `/admission` through the real gateway. Cookie/CSRF remain in memory.
   Do not synthesize Unix identity headers, extract passwords, change memberships
   or persist native cookies. A200 auth-mode or loopback health is not admission.
   Source qualification uses reads only; do not write live house data for testing.
5. Wrapper validates both pinned executables (canonical regular executable,
   non-group/world-writable, exact SHA256/UID/mode and stable file identity).
   Tunnel `--version` must match metadata before runtime-key bytes are read.
   It constructs only the inspected0.0.14 flags: official host root
   `https://api.openai.com`, existing registration, API-key environment reference,
   shell-quoted fixed Python `-I -B` stdio launcher, max concurrency/inflight1,
   initialized-notification shim, health `127.0.0.1:0`, state `health-url`, info JSON
   logging. No /v1/dev suffix, arbitrary control-plane URL/argv, unadvertised PID
   flag, mTLS/CA/proxy/cloudflared changes. LaunchAgent owns process identity.
6. After separate staging review, the user runs the setter in their own trusted
   Terminal via existing SSH with allocated TTY (`ssh -tt`, never -n/-T), preserving
   existing host verification and NAS-owner options BatchMode=yes,
   StrictHostKeyChecking=yes, UpdateHostKeys=no, ControlMaster=no, ControlPath=none.
   The command uses the exact privately pinned Python with `-I -B` and the absolute
   stable top-level key-entry.py path. No value appears in the command or chat;
   user reports only “stored”. The setter activates nothing.
7. Metadata-only readiness may inspect key type/UID/link/mode/existence; never read
   key bytes or derive a fingerprint. NAS owner separately owns LaunchAgent setup,
   activation, rollback and acceptance. This source creates no plist/listener.

Health checks use only a validated owned numeric loopback URL from `health-url`,
GET `/healthz` and `/readyz`, status only. No UI/metrics call is needed.

## Key and session custody

The setter enforces the private contract's UID/EUID and canonical owned0700 config
parent. Mandatory `/dev/tty` has no stdin/getpass fallback. Bounded noncanonical
noecho input drains rejected lines through newline while staying noecho. INT,
TERM, HUP, QUIT and TSTP abort through terminal restoration. Create-only raw key
uses O_EXCL/O_NOFOLLOW, mode0600, one link, exact owner, complete writes and
file/directory fsync. No replacement, retry, deletion of partial files, secret or
fingerprint output, or activation.

The wrapper passes the raw key only through CONTROL_PLANE_API_KEY to the existing
tunnel client, never shell source/eval, argv, plist, spec, logs or receipts. The
native stdio launcher clears that environment. Bridge canonical gateway sessions
stay in memory, with actor/scope validation, between-action reissuance, and
best-effort logout on EOF/INT/TERM/HUP/QUIT followed by memory discard. No persistent
native-session.json or user-cookie extraction exists. Failed logout remains
unconfirmed; no fabricated revocation claim.
