# Provider and AI integration policy

## Decision boundary

These application requirements describe stock HomeBox and official Sign in with ChatGPT (SIWC)/Responses interfaces. Static contracts and synthetic fixtures do not establish provider qualification, live write readiness, live SIWC eligibility, a supported server credential route or permission to spend credits. Keep those gates explicit and independently enforced. Static source adoption requires no live credentials, registrations, grants or inference.

The policy and capability fields are server-issued. Clients and models cannot select authority, qualification, policy, actor, home, affected scope or approval. Separate authenticated transports use the same authorization and command service.

## Stock HomeBox contract

| Field | Contract meaning |
| --- | --- |
| `policyVersion` | `at35-stock-approved-1` |
| `providerStrategy` | `stock-homebox-scoped-atlas-writes` |
| `decisionScope` | `approved-stock-strategy-for-implementation` |
| `atlasOwnedCASRequired` | `true` |
| `atomicProviderCAS` | `false` |
| `allWriterFence` | `false` |
| `nativeEditorRacePossible` | `true` |
| `providerQualified` / live readiness | Independently established for the exact build, runtime, routes, storage, source registration, home mapping and grants; static implementation decisions cannot set these true. |

Preserve strong Atlas `expectedRevision`, local CAS, authorization, graph/final-state validation, durable identity/source-key reservations and append-only rules. The local record, audit and idempotency receipt commit atomically. Atlas atomic batches exclude provider writes. No Atlas database transaction spans provider HTTP.

Use a server-issued opaque `providerObservation` handle/digest bound to the actual source, collection, target, versioned normalized fields and observed impact. Re-read immediately before dispatch. A changed observation or impact produces `preflight-conflict` before dispatch. A matching observation does not exclude a later native write or stale native save; it is not a provider CAS revision.

Derive entity, affected-resource and collection scopes on the server. Broad/shared scopes conflict with contained narrow scopes. Every Atlas path and instance participates in the durable queue and fence ownership. Every provider mutation uses the single physical-database dispatcher, even when logical scopes are disjoint. Independent reads and preparation may proceed concurrently; logical overlap fences remain separate. Read, search, inference and file preparation do not require a global write lock.

Recheck actor/home/source/resource authority before dispatch and reconciliation, including expiry and revocation. An approval/impact receipt binds the exact payload and known effects, with changes rechecked before dispatch. Shared or cascading writes require enforceable authority over the affected scope, such as the complete affected collection; a broad backend key does not confer another home's permission. Action-specific permanent-delete review remains required. Stock HomeBox cannot freeze later native impact.

Prefer a supported narrow PATCH. For whole PUT, read current stock state and change only intended fields while preserving untouched scalars, dates, parent, tags, custom fields and sync values. Omitted/preserve, supported explicit clear, empty and zero are distinct. Unsupported clear or variant rejects before effects. This preservation applies at the read boundary; native changes afterward can race. Parent clearing must use its qualified actual form; PATCH null must not be assumed to clear the root.

### Single dispatch, uncertainty and reconciliation

Persist the immutable pending intent and overlapping scope fence before dispatch. Durable deduplication binds actor, home, key and canonical intent digest. The same key with a changed intent rejects; a known completed duplicate returns saved historical evidence without another dispatch. Local deduplication is not provider idempotency or an exactly-once create guarantee.

After dispatch starts, a timeout, crash, lost response, ambiguous error, provider success followed by local-finalization failure, or readback mismatch retains the original key/payload and scope fence across restart. Release ordinary CPU/database resources while retaining logical fences and liabilities. The physical dispatch gate remains held until correlated remote termination is proven; timeout, lease expiry and human effect resolution do not prove termination. Do not automatically resend ambiguous non-idempotent work or dispatch dependent destructive work. Takeover and snapshot recovery cannot infer safe redispatch. Reconcile through trustworthy correlated evidence or explicit audited human resolution. A current value, matching name/size, list absence, or guessed timestamp is insufficient correlation for an ambiguous create/upload. Provider busy/generic failure establishes no effects only when that exact route proves it.

Persist actual response identities and sanitized route-specific readback/effect evidence. Report `confirmed-observed` only when the success response and required evidence agree; record `verification='observed-after-write'` and the observation timestamp. Readback can verify current state, but cannot prove which writer caused it: `causalityProven=false`. Missing generated identities, partial effects, native interference and errors remain distinct. A bulk-shaped response must not be used to guess a new attachment identity. Delete confirmation requires qualified scoped not-found evidence, not a generic server error. A mismatch after reported success is unsafe for automatic retry.

Preserve these lifecycle semantics even if the service maps them to an existing enum: `prepared`, `queued`, `dispatching`, `confirmed-observed`, `rejected-before-dispatch`, `partial`, `unknown-held`, `resolved-observed`, `resolved-by-human`. `unknown-held` requires `unknownScopeFenceRetained=true`. Human resolution records actor/evidence without inventing a provider transaction receipt. Outcome verification distinguishes `observed-after-write`, `current-state-observed-only`, `human-reconciliation`, `unresolved` and `no-dispatch`.

### Capabilities and effect boundaries

Capability status distinguishes `supported-pending-qualification`, `qualified`, `unsupported-stock-form`, `held-policy` and `forbidden-append-only`. Unsupported, held and forbidden forms do not require successful execution and reject before effects. Verification distinguishes `Atlas-atomic-CAS`, `provider-observed-best-effort`, `atlas-mediated-history-only`, `qualified-read` and the corresponding before-effects states.

Retain complete supported inventory/location CRUD, parent/type/archive, tags/custom fields, templates/duplicate, native parent-location sync, attachments/external links/metadata/delete and maintenance scheduling/completion/reopen. Real additional routes need typed bounded mapping and authorization, including imports/exports, queries, lookup/labels/reporting and approved bulk actions. The nine absent lifecycle/history forms are typed unsupported optional capabilities; absent candidate rows for actual routes are mapping work. Credential/account/group/notifier and backup/admin routes retain separate security/operations boundaries.

Provider operation history has `coverage='atlas-mediated-only'`; complete native/internal history is unsupported. Distinguish the genuine HomeBox archived toggle from Atlas local archive/tombstone/restore using `archiveAuthority`. Atlas restore cannot claim provider row/blob restoration; native permanent deletion has no ordinary undelete form. Child sync follows actual stored native behavior and observed impact, including race/partial results; arbitrary child subsets and null-parent propagation remain unsupported variants. Preserve or expose stored sync behavior during update/reparent.

Media qualification covers actual streaming size/type/time limits, authorized entity/file identity, bytes/hash/download/thumbnail behavior and possible partial effects. Stock does not promise immutable stages, byte versions, a purge outbox or provider undelete. Compound provider workflows report per-step effects and partial/unknown outcomes rather than cross-provider atomicity. Restore Atlas ledger, keys, bindings and fences coherently; restored dispatched work stays held until reconciliation. Qualify coherent provider database/blob backup and controlled restore separately.

### Write readiness holds

Before live writes, qualify the exact artifact/version/hash and any narrow provider error repair; runtime/storage/schema; registered source and home collection mapping; exact grants, cross-user/home denial, expiry/revocation; route-specific payload/preservation, response identity and readback; native-race limitations; partial and lost-response handling; crash/restart queue ownership; media/delete behavior; and recovery. Saved architecture choices, synthetic schedules and mock successes do not establish production readiness. Qualification must resolve false success/error behavior and receive acceptance for that exact target. Native same-field overwrites are an accepted concurrency limitation; unauthorized home/cascade effects are not.

## Official SIWC and Responses implementation

Implement connection UX, documented local OAuth components, a public Responses adapter, explicit trusted-runtime interfaces, authenticated shared tools and synthetic identities/tokens/transports. Keep live runtime selection unset until qualified. Server-hosted inference remains the desired deployment; the interface does not silently adopt an always-running local inference companion.

The documented local flow uses `http://127.0.0.1:<available-port>/auth/callback` on the computer running the authorization browser. Only the port varies; authorization and exchange use the same URI. A browser's loopback callback does not reach a separate server. A server HTTPS callback needs an issued client and exact registered callback; website identity support alone does not establish plan-use access. The documented remote-VM transfer case does not by itself establish a supported server credential route. Keep unresolved transfer and server-owned refresh mocked. [Local availability](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt), [sign-in contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [remote-VM procedure](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms), [website callback contract](https://developers.openai.com/siwc/website).

Keep three candidates distinct: a sign-in-only local helper with conditional supported server credential placement; an issued website client with registered server callback; and a per-user local inference companion whose credentials, refresh and Responses calls all remain local. The local companion requires its execution computer to remain available; mobile relay availability is unverified. Any permanent client/runtime dependency and mobile trade-off requires a concrete deliberate choice before adoption. An unresolved route proves neither refusal nor eligibility.

For the documented local component, use fresh state, OIDC nonce and PKCE-S256; validate identity and granted plan-use scope before activation; retain the callback's issued client. The reference local SDK uses `sendHostId:true`, an absolute storage directory and OS-backed encryption. Maintain a separate account/workspace registration and credential boundary for each person; never share a single active-profile slot across concurrent users. Keep tokens out of browser state, logs and ordinary exports. [Sign-in contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [pinned SDK configuration](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/f723814abdccec135b519c451fb6e1992ee5e933/packages/local/src/types.ts).

A candidate local bridge is application design requiring mocks and target QA. Pair it with an authenticated application principal and approved server origin; bind each turn to actor, home, provider registration and cancellation epoch. Use a local UI or narrowly authenticated loopback bridge with origin/Host checks, an unguessable per-install capability and request validation. Do not use wildcard CORS or an unauthenticated LAN listener. Application authentication is separate from SIWC. Browser secure-context/local-network behavior and any phone relay remain unqualified; unavailable runtime/bridge must visibly disable AI.

Use `https://api.openai.com/v1/responses`, `store:false`, `stream:true`, account-specific models and complete required history. Require `response.completed`; an incomplete/error stream cannot record completed inference. The application retrieves authorized context and dispatches namespaced function/custom tools itself. Do not assume hosted MCP or file search support. The pinned DevKit text helper exposes neither tools nor a raw token getter; implement/review a tool-capable adapter inside the selected trusted runtime's credential boundary and keep it mocked until runtime/grant qualification. Never extract another application's sessions. [Models/inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [pinned helper](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/f723814abdccec135b519c451fb6e1992ee5e933/packages/local/src/responses.ts).

Serialize refresh per registration using its issued client/resource, and atomically persist rotated tokens. Preserve inaccessible/corrupt encrypted state without plaintext fallback. Disconnect stops local use, attempts documented revocation and clears local tokens; failed remote revocation stays visibly unconfirmed. Registration retention and provider disconnect detection remain separate; independent transferred-host revocation is not claimed. [Accounts/sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [pinned storage](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/f723814abdccec135b519c451fb6e1992ee5e933/packages/local/src/storage.ts).

Sign-in must not automatically run inference. Identity alone cannot enable plan use. Real inference remains disabled until zero paid use is verified or concrete credit spending is approved: the supplied guidance did not establish a request-level plan-only credit opt-out. Show active account, plan-use state and Manage usage; no automatic credit opt-in, API-key fallback, unofficial backend or guessed unlimited-plan promise. Model discovery and completed inference are separate qualification observations. [Usage guidance](https://developers.openai.com/siwc/ui-ux-guidelines).

### Runtime failure and synthetic fixture contract

Preserve sanitized HTTP status, structured code/parameter and request ID; provider detail prose is not a stable code. Rejected consent, callback/state/nonce/audience/identity or unsupported eligibility prevents activation and model use; retain a previously valid connection separately. Missing plan scope shows signed-in/plan-use-disabled and requires explicit consent action. Storage failure stops use without plaintext fallback. Grant/admission 401/403 diagnoses account/scope/client without billing changes; 429 pauses and offers Manage usage without inventing a reset time; temporary 503/network failure preserves credentials and uses bounded backoff. Unsupported-parameter 400 identifies the parameter and does not retry identically. Terminal refresh failure clears unusable tokens and requires explicit reauthorization with the saved client; never replay a consumed refresh. `invalid_client` requires configuration repair, not repeated consent. [Official recovery guide](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

At every tool dispatch, validate typed arguments and actor/home rights on the server, reusing revision, idempotency, approval and reconciliation rules. Logout, account/home change or cancellation stops pending model work and future dispatch; reconcile already-submitted mutations without rollback promises or blind replay. Mock fixtures cover these failures, callback-port variation, invalid state/nonce/audience, missing permission, denied cross-home commands, rotating-refresh concurrency, duplicate mutation recovery and aborted streams. Synthetic success never establishes live eligibility.

### SIWC live qualification holds

Before actual sign-in, obtain concrete access approval for the reviewable supported runtime, exact callback and each user's account/plan-use grant. Establish a supported route covering credential placement and refresh on that runtime; local-helper success alone does not establish server eligibility. Observe the issued client, validated identity/account/workspace binding and granted plan-use scope. Qualify encrypted storage, refresh, disconnect and per-user application authorization. Before inference, pass the independent paid-use guard, then separately observe model discovery and a completed response. Any permanent local companion requires the explicit availability/mobile choice above. These are live holds, not implementation blockers.

The official SDK reference is `openai/sign-in-with-chatgpt-devkit` at public commit `f723814abdccec135b519c451fb6e1992ee5e933`. The public documentation links above are supplied references; this static summary does not newly verify provider availability or perform live qualification.

## Qualification and execution boundaries

All listed failure/denial/replay/expiry/revocation/crash/concurrency and guard/reversal/mutation/omission qualification requirements remain unexecuted in this integration. Contract adoption does not release stopped checks or authorize live effects. Ordinary compiler/build work and named healthy examples are distinct from security, provider and production qualification. The single physical-database dispatcher rule applies even to disjoint logical scopes.
