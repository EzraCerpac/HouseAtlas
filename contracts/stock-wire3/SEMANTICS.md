# Language-neutral application contract semantics

These are implementation requirements accompanying the stock.2 wire3 JSON contracts and source-presence semantics 1.1.0. They do not establish provider, security, target, account, production or live-write qualification. The production target is one Rust application, React with strict TypeScript, SQLite and immutable media. Prior JavaScript is reference material, not a production dependency. New source-presence admission remains held until the Rust transaction, authority and recovery composition is reviewed.

## Contract identity and offline resolution

The active stock contract is `0.3.0-at34.stock.2`, agent wire3, with frozen Atlas contract1.0.0 and record/audit schema1. Preserve the 158 historical command IDs and six additional typed groups, their 164 request/result arms, ten proposed tool families and all route dispositions. Families are transport groupings, not permission to expose arbitrary HTTP. Historical wire2 metadata does not override current stock dispositions. The stock schema's historical `$comment` is not its adopted package identity; the adoption manifest and catalog identify stock.2.

Use the accompanying `resource-map.json` offline resource map. Register the frozen Atlas schema by its exact canonical `$id`; resolve source-presence relative references offline to the same bytes. Keep draft2020-12 semantics, union arms, required fields, nullability, closed properties and scalar constraints. JSON Schema string lengths count Unicode code points; Rust/TypeScript ports must not replace these with UTF-8 byte or UTF-16 code-unit limits. Preserve safe-integer bounds and exact canonical JSON/SHA256 conventions across languages. Static adoption does not establish generator or runtime conformance.

## Runtime correlation required beyond schema shape

Every committed Atlas result, including remap and batch, must carry `data.requestDigest` equal to the accepted request's intent digest. The intent includes its operation key, payload and local guards; renewable observation, human receipt and transport request IDs do not create a new intent. Root and ordered child request IDs, keys, targets, guards and payloads must remain lossless in native batch storage and result mapping. Only the requestDigest call's root requestId and approvalReceiptId are excluded; a HomeBox target also excludes its renewable preconditions.providerObservation. Child requestIds remain inside the parent batch intent digest. Do not recursively strip child transport IDs from the parent intent or normalize ordered arrays. A declared schema arm alone does not qualify its implementation.

Correlate `data.target`, each `resources[].target` and each targeted `rows[]` result with the authorized command. Check authority, source/collection partition, declared result kind, actual owner and exact existing identity. Atlas asset media results must name the exact requested target. New provider identities and ancestor-path results use only their specifically defined exceptions; generic resource acceptance cannot replace output graph authorization. Preserve the distinction between input/source authority and output disclosure authority.

Invoked provider outcomes use only `active`, `end-unproven` or `ended-proven` remote activity. `not-dispatched` belongs to never-invoked outcome states or an idle dispatcher, with empty effects and no claimed success. An ended request can retain unknown effects and logical fences. Parse operational observation/approval/enqueue/expiry/admission clocks to finite times before comparing them; broad RFC3339 shape acceptance alone does not establish finite operational clocks or correlations.

## Current authority, local atomicity and approvals

All human, MCP, WebMCP, AI and background mutation paths call one domain service. Clients select context/targets; they do not mint actor authority, source grants, provider qualification, approval receipts, epochs or timestamps. Resolve the complete target/reference/impact graph and current home/source/collection capability at preparation and final dispatch. Whole-collection actions require the actor's real whole-collection entitlement. A broad backend credential does not supply it. Authorize every disclosed result and any retained receipt against current authority.

Atlas-owned records retain local revision CAS, immutable source keys, guarded final graph checks, permanent reservations, append-only provenance and atomic record/audit/receipt commit. Use a dedicated blocking SQLite write owner for a bounded complete transaction. Revalidate the captured authority facts and original grants immediately precommit; replacing a grant or rebasing a generation does not satisfy the original intent. Provider HTTP remains outside SQLite transactions. Cancelling an HTTP caller cannot undo a SQLite operation already running.

Only the separate trusted human UI can issue approval. Bind approval to actor/home/target, exact immutable intent and impact, policy/authority epochs and expiry. Admission atomically consumes/binds it with the operation/reservations/receipt rather than spending it during preparation. Generic tools cannot approve their own actions. Permanent provider deletion retains action-specific approval and qualified recovery limits.

## Stock provider and durable dispatch limits

HomeBox remains inventory/location/file/maintenance authority. Atlas observations and caches do not create atomic provider CAS, upstream idempotency, causal proof or all-writer fencing. Native UI/API/internal writers remain available outside Atlas ordering and can race. Preserve omission/null/empty/zero differences and route-specific clear/time semantics. Native child synchronization preserves the inspected `syncChildEntityLocations` behavior; it is not an arbitrary selected-child transaction or physical room-tree proof.

Use one durable queue and one exclusive invocation per actual physical provider database in the single deployment. All configured aliases, collections, transports and provider-mutating jobs join it. Reads, preparation, inference and Atlas-local CAS stay concurrent. Logical overlap fences retain their narrower meaning; an end-unproven physical invocation blocks new provider invocations even when logical scopes differ. Durable owner/epoch correlation must fence and quiesce stale local dispatchers. No distributed coordinator or provider-side fencing token is claimed.

Waiting entries contain bounded metadata with `bodyAccepted=false`; accept/stage upload bytes only after exclusive dispatch admission and qualified liability reservation. Waiting expiry can finalize only a never-dispatched attempt. Timeout, cancellation, disconnect, crash, lost reply or missing readback cannot prove rollback or remote termination and cannot authorize redispatch. Persist dispatch intent before invocation. Retain unknown outcome fences, activity holds and byte/orphan liabilities independently. Human effect reconciliation does not prove remote end. Only correlated qualified termination evidence releases the invocation hold. No cap, missing row, filename/hash match or age grants cleanup authority.

The accompanying engineering profile's one active mutation, four waiting intents, 10-second admission wait, four unresolved storage attempts and 64MiB reserve are offline engineering numbers. They are neither measured capacity nor user-selected deployment settings. Unknown accounting retains `reservedBytes=null`, never fabricated zero. The engineering profile does not establish actual provider/source/grant/route qualification.

## Closed routes and special forms

Preserve the accompanying 96-route disposition table and 21 grouped feature routes. Security/account/operator/diagnostic routes outside the domain do not become generic tools. Nine absent stock lifecycle/history forms remain explicitly unsupported before dispatch; mediated history records Atlas operations, not native provider history. Atlas restore does not undelete provider data. Provider archive/unarchive changes the actual preserved HomeBox field and is distinct from Atlas lifecycle.

Collection-wide bulk/import/export/statistics/maintenance forms require whole-collection authority and authorized output scope. Label rendering explicitly disables print; `print=true` is an upstream GET with a physical side effect and needs mutation admission, idempotency/impact/approval and a qualified printer. Barcode lookup is separately qualified external egress. Product URLs/base64 become bounded authorized media handles, never arbitrary-fetch tools. The Network facet stays passive `GET /api/inventory`; no collector, diagnostic, lease or inventory mutation path is introduced.

## Presence observations and witnesses

The current semantic scope is only HomeBox entities, Network devices and Network groups. Magicplan is a separate future feature. Presence means observed in the specified successful local generation at its saved time, not live existence at admission. Only the latest visible complete successful publication, fresh under the existing cache-age policy, can qualify an exact compatible member. Filtered pages, relation endpoints, quarantined/revoked/incomplete/failed/unavailable state and guessed generation IDs do not establish membership. Fetching under the Atlas write lock is not required or allowed as a substitute for captured facts.

New triggers are create-present, nonpresent-to-present, restore-active-present and replacement of the evidence-ID membership set while present. Adding/removing/replacing an ID triggers; reordering the same unique IDs does not. Set comparison is only for this trigger: preserve submitted arrays, request/receipt digests and ordered batch semantics. Review-status-only edits retain the earlier witness. Mapping acceptance alone can leave the binding unresolved and never implies positive availability.

Storage derives assertions from the actual original/candidate/final graph and stamps immutable witness linkage from the committed binding revision, audit, mutation, actor and scope. Trusted qualification supplies only the allowed exact member/cache/authority observation facts. Recheck complete original/candidate/touched/guarded/referenced source authority, publication pointer/cache epoch/member/type/freshness and captured grants in the active transaction and immediately precommit without substitution or rebase. Witness, binding, audit and receipt persist atomically and recover coherently. A service sidecar is not an atomic substitute.

Keep cache successful-fetch observation time separate from audit admission time and raw source update/snapshot/retrieval times. HomeBox member and registration digests use canonical exact rows. Network member digest uses the complete normalized member; generation digest uses verified immutable saved full-state bytes, not reserialization or a filtered display. Access epoch is opaque persisted text; context UUID is correlation only; registration version/digest comes from the real enabled row. No session secret, serialized grant, hidden guessed version or provider-revision overload belongs in the witness. Historical disclosure needs current authority but does not refresh presence; never fabricate legacy witnesses. Witness metadata has no automatically authorized browser endpoint.

Frozen record/audit schema1 remains unchanged. Old core witness schema4 and native admission profile5 are distinct historical storage lineages, not a migration instruction for fresh Rust state. Adopt an explicit fresh Rust schema/profile and typed composition; do not merge old profiles or silently enable presence from a copied policy flag.

## Official in-app AI decision

The AI interface uses official SIWC/Responses. Actual server registration/account/consent/callback/credential/inference eligibility remains unverified; static contracts do not establish it. Use the same authorized domain service and minimal private context. Do not substitute borrowed sessions, undocumented callbacks, automatic paid API fallback or silent credit consent.

Keep a supported sign-in helper distinct from a persistent inference companion. Server-hosted inference and mobile usability remain product goals. A local OAuth result or official open-source remote-VM example does not qualify server credentials or inference. Any awake-client, phone, pairing, network or protected-credential dependency requires an explicit runtime decision before becoming a requirement; Rust must not silently turn the product into an always-awake client backend. Official documentation and actual eligibility require separate verification; this static policy does not verify current external availability.

Guard, mutation, omission, reversal, adversarial, denial, rejection, replay, expiry, revocation, failure, crash and concurrency controls remain unrun in this integration. Contract adoption does not release stopped checks. Ordinary source/compile/healthy-example work and full security/provider/product qualification remain distinct.
