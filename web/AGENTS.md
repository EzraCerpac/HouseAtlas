# HouseAtlas UI copy

These rules apply to all files in `web/**`, including future redesigns, generated
UI and external design briefs. Include this policy in a design tool's prompt
when that tool cannot read the repository instructions.

Every piece of interface text must identify data, an action, a state or a
specific limitation. Use short functional headings such as Home, Rooms & places,
Documents & links and Settings.

Do not add slogans, taglines, welcome promises, mission statements, decorative
introductory paragraphs or instructions that merely describe an obvious link or
control. Do not fill available space with prose. Do not replace removed filler
with a different slogan. Express visual hierarchy through layout and actual
content.

Keep necessary guidance once, beside the relevant control or failure. Prefer a
precise field label to an additional helper paragraph. Show an explanatory
sentence only when it supplies information needed for the current action or
interpretation that the surrounding label or state does not already provide.

Preserve accessible names, focus targets and factual information: scope, source
ownership, unknown or unplaced records, uncertainty, successful-update dates,
stale data, access denial, file availability and evidence qualifiers. Preserve
source-owned descriptions and notes as data. Concision must not conceal a
failure, imply fresh information or invent availability.

Before delivery, review every added sentence: what data, action, state or
limitation does it communicate, and is that information already visible?
Remove it if it has no concrete purpose or repeats nearby text. Apply this
review to all pages and states, not only the landing page.
